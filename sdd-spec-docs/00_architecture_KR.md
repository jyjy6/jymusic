# Jymusic 프로젝트: 아키텍처 헌법 (사람 중심 가이드)

## 1. 시스템 개요
Jymusic 프로젝트는 음악 앨범 판매 이커머스 서비스를 위한 마이크로서비스 아키텍처(MSA) 기반의 플랫폼입니다. 현대적인 웹 표준과 확장 가능한 구조를 목표로 합니다.

### 1.1 핵심 기술 스택
- **프론트엔드**: Nuxt 4 (Vue 3, TypeScript, Nitro 엔진)
- **백엔드**: Spring Boot 3.x / 4.x (Java 21), Spring Cloud
- **API 게이트웨이**: Spring Cloud Gateway (WebMvc)
- **데이터베이스**: MySQL (서비스별 데이터베이스 독립 패턴)

## 2. 기본 원칙 (아키텍처 헌법)

### 2.1 프론트엔드 개발 표준 (Nuxt 4)
- **컴포넌트 구조**: 반드시 `<script setup lang="ts">`를 사용합니다.
- **API 통신**: 반드시 **Axios**를 사용하여 모든 외부 및 내부 API 호출을 처리합니다.
- **상태 관리**: 중앙 집중형 상태 관리가 필요한 경우 Pinia를 사용합니다.

### 2.2 백엔드 개발 표준 (Spring Boot)
- **전역 에러 처리**: 비즈니스 로직에서 발생하는 모든 예외는 반드시 `GlobalErrorHandler.GlobalException`을 사용합니다.
- **예외 처리 패턴**: 중앙 집중형 `GlobalExceptionHandler`를 통해 일관된 에러 응답 포맷을 제공합니다.
- **API 게이트웨이**: 모든 클라이언트 요청은 `jym-api-gateway`를 거쳐 라우팅됩니다.

### 2.3 테스트 및 품질 관리
- **단위 테스트**: 모든 서비스에 대해 단위 테스트 작성을 의무화합니다.
- **테스트 커버리지**: 전체 코드의 단위 테스트 커버리지를 최소 **70% 이상** 유지해야 합니다.
- **통합 테스트**: 현재 단계에서는 작성을 보류하며, 단위 테스트의 품질에 집중합니다.

### 2.4 스펙 기반 개발 (Spec-Driven Development)
- 모든 API 변경은 OpenAPI Specification (OAS 3.0/3.1) 정의에서 시작합니다.
- 문서는 '진실의 원천'이며, 실제 구현은 이 스펙을 엄격히 따라야 합니다.

## 3. 통신 및 보안 원칙
- **RESTful 표준**: REST 성숙도 모델 2/3 단계를 준수하며 명확한 HTTP 메서드를 사용합니다.
- **무상태성(Statelessness)**: 세션 상태를 서버에 저장하지 않으며 JWT를 통해 인가 처리를 수행합니다.
- **데이터 독립성**: 각 서비스는 자신의 데이터를 소유하며 다른 서비스의 데이터베이스에 직접 접근하지 않습니다.
